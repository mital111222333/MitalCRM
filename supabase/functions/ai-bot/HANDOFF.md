## 3. Архитектура (версия 1, готова и запушена)
Telegram (новый отдельный бот) → Supabase Edge Function `ai-bot` (Deno, один файл) → Google Gemini (function calling + аудио).
- Отвечает Telegram сразу, а работу делает в фоне через `EdgeRuntime.waitUntil`.
- Доступ только для Telegram ID из `ALLOWED_USERS`. Чужим бот сообщает их ID.
- Webhook защищён заголовком `x-telegram-bot-api-secret-token` = `TG_SECRET`. Подключение одной ссылкой: `<url функции>?setup=<TG_SECRET>`.
- Отдельный бот нужен потому, что у бота для агентов уже есть webhook на Cloudflare Worker (`worker.js`), а webhook у бота может быть только один.
- Почему Supabase, а не Cloudflare: на бесплатном Cloudflare лимит CPU 10 мс, а `crm-data.json` весит около 3,4 МБ. У Supabase на бесплатном тарифе 2 с CPU.

**Секреты:** `TG_TOKEN`, `TG_SECRET`, `ALLOWED_USERS`, `GEMINI_KEY`, `GH_TOKEN` (fine-grained, Contents: Read-only на `mitalcrm-data`). Необязательные: `GEMINI_MODEL` (по умолчанию `gemini-3.1-flash-lite`), `GH_OWNER`, `GH_REPO`, `TZ_NAME` (Asia/Tashkent). У функции должен быть выключен Verify JWT.

### Экономия запросов к Gemini (бесплатный лимит считается по запросам в день)
- Простой вопрос = 1 запрос. Gemini выбирает функцию, а ответ собирается по шаблону (`TPL`). У каждой функции есть служебные поля `explain` (true → второй запрос, ИИ пишет анализ сам) и `heard` (расшифровка голосового).
- Быстрые команды без ИИ: `/today`, `/dolg [агент]`, `/agents`, `/k имя`, `/sleep`, `/sklad товар`, `/data`, `/fresh`, `/new`, `/help`.
- Кэш: тот же вопрос в течение 5 минут, если между ними ничего не спрашивали, отвечается из памяти.
- Данные из GitHub кэшируются на 2 минуты. Архивные дни кэшируются навсегда, кроме двух последних.

## 4. Данные (`mitalcrm-data`) и правила подсчёта
- `linko-fast.json`: свежие orders, items, pays, debtors (автозагрузка `autolinko.gs` каждые 5 минут).
- `linko-extra.json`: returns, freq, workday, workper (агенты за период), rejects, recom (рекомендация по складу), prods.
- `archive/YYYY/MM/YYYY-MM-DD/fast.json.gz`: снимки по дням, каждый с начала планового периода. Бот склеивает все дни и убирает дубли по `id`, при этом более поздний снимок важнее. История есть **с 16.10.2026**.
- `inst-state.json`: рассрочка. По каждому клиенту: debt, late (просрочено), today, next, age, lastPay, заказы с графиком частей. Плюс договоры и `texts.me` (готовая сводка по дебиторке).
- `crm-data.json.gz` (`state`):
  - `ag.clients`: имя → агент, телефон, ориентир, тип
  - `ag.uploads[-1]`: последний баланс-файл за период (b0, sold, ret, paid, b1; оплаты по карте учтены тут)
  - `wh.uploads`: остатки складов Ташкент, Фергана, Наманган
  - `ext.payPlan`: обещания оплат
  - `ext.agentPlans`: планы
  - `ext.inst.contracts[].files`: сканы договоров, лежат в `contracts/<id>/...`
  - `ext.pay`: зарплата, см. `pay.js`
  - `ext.disc`: дисциплина и штрафы
- Плановый период: с 16-го по 15-е.
- Тип оплаты: 1 = оплата, 3 = возврат, 4 = списание по заказу. Учитываются только USD (в данных есть одна оплата в SUM).
- Статус заказа: 1 = новый, 3 = отгружен, **4 = отменён (в продажи не входит)**.
- Агент клиента берётся из `ag.clients[name].agent`, как в CRM (`lx.js`).
- Наличные видны в транзакциях LINKO, переводы на карту только в баланс-файле. Бот показывает их отдельно.
